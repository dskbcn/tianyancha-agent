# Spike 0.4: web plumbing (preview)

Status: done, 2026-10-22. Plan item: `docs/plans/company-agent.md` 0.4. Built as a working
preview on branch `feat/0.4-web-preview`: `packages/company-db`, `apps/agent`, `apps/web`.

Question: how does a browser UI talk to the eve agent, how are result files downloaded behind
the same auth, and does the whole harness (streaming, tool activity, tables, stop, resume) work
against the real MCP data and Bailian model?

## Decision: own Vite app on `useEveAgent`, same origin through a proxy, downloads as an eve route

```
browser ── :5173 Vite (apps/web) ──/eve/*, /files/*──▶ :2000 eve dev (apps/agent)
                                                         ├─ eve channel (chat, stream)
                                                         └─ files channel GET /files/:session/:name
production: Caddy serves the web build at / and proxies /eve/* and /files/* to the agent
```

- **Not `eve add channel/web`.** The installer is Vercel-first: run non-interactively with
  `web-framework="tanstack"` and `--skip-install`, it still wrote a Next.js config stub and a
  `vercel.ts` with Vercel services, and asked for "Sign in with Vercel". Its React components are
  embedded in eve's dist (`setup/scaffold/create/web-template`), which was useful as a reference
  for message parts, but we self-host. The preview is a Vite + React 19 + Tailwind 4 app on
  `useEveAgent` from `eve/react` (no framework integration needed).
- **Same origin, no CORS.** Vite proxies `/eve` and `/files` to the agent; Caddy does the same
  in production. In dev, the eve channel's `localDev()` admits the proxied requests.
- **Downloads are a custom eve channel** (`apps/agent/agent/channels/files.ts`): `GET
  /files/:sessionId/:name`, behind `routeAuth(request, routePolicy(...))`, so it shares the
  chat's auth. Tools write CSVs to `OUTPUT_DIR/<sessionId>/`. Verified: 200 with
  `content-disposition: attachment; filename*=UTF-8''…`; `..%2F..%2Fpackage.json` gives 404.

## Findings

1. **The browser gets the full tool output; the model gets the summary.** `toModelOutput`
   returns a short Markdown table (≤ 30 rows) to the model, while `action.result` carries the
   whole object to the client. The UI renders a 100-row preview, the SQL, timings, warnings,
   the `find_companies` score distribution and the CSV link from it, none of which enters the
   model's context.
2. **Tool labels drive the activity UI.** `label.start(input)` and `label.complete(input,
   output)` appear as `part.toolMetadata.eve.label`. We added a `purpose` input to `company_sql`
   so the label reads as what is being computed ("深圳 2020–2025 年各年成立企业数…：6 行，16.0
   秒"). `label` must be declared after `execute`, or TypeScript types `output` as `unknown`.
3. **Parallel tool calls happen.** The model issued two `company_sql` calls in one step; the
   client's 3-call semaphore (spike 0.3) covers it.
4. **Stop works.** `agent.cancel()` during a running query ended the turn (`turn.cancelled`)
   and the composer was ready again within 2 s. The UI shows "已停止". Steering a running turn
   (`turnPolicy: "steer"`) is wired into the composer but not yet exercised.
5. **Resume works from saved events.** Each chat keeps `{ session, events }` in localStorage;
   a reload re-renders from the events and reattaches with `resume: true`. One two-query
   conversation is 870 events (mostly `reasoning.appended`), so localStorage fills after tens
   of chats. A server-side chat list replaces it in phase 1.
6. **Timings in the UI.** A typical SQL answer takes 50–60 s end to end (two scans of ~16 s
   plus model time); `company_find` alone took 54 s. A live per-tool timer and the "查询中"
   status keep this readable.
7. **eve dev reads only `.env.local` in the app directory.** `apps/agent/scripts/with-env.sh`
   exports the repo-root `.env.dev` before running eve.
8. **Agent behaviour seen in the preview, fixed in instructions and skill, not yet re-run:**
   - One pre-tool narration line came out in English. Added: all output in the user's
     language.
   - "近一年杭州做人工智能的公司" hit the 5,000-row `find` cap (38,636 keyword candidates).
     Added: when the result says it hit the cap, re-run with `minScore` from the distribution
     so the CSV is complete.
   - With `IS DISTINCT FROM` the agent counted 14,961 companies for 杭州 2026-08, against
     14,959 with `<>` in spike 0.3: the 2 rows with NULL `enterprise_type` are now kept.
