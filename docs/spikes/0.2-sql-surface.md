# Spike 0.2: SQL surface and data

Status: done, 2026-10-22. Plan item: `docs/plans/company-agent.md` 0.2.

Question: what SQL can the agent write against `query`, what do the columns really contain, and
what must every answer say about coverage?

## SQL that works

The whitelist allows everything tried: CTEs, window functions (`RANK() OVER`, `SUM() OVER ()`),
`COUNT(*) FILTER (WHERE …)`, `CASE`, subqueries, `JOIN` across the two tables, `LIMIT/OFFSET`,
and the functions `regexp_replace`, `substring(… from '<regex>')`, `to_char`, `date_trunc`,
`LEFT`, `ROUND`, regex match `~` / `!~`, casts `::date` / `::numeric`.

## Findings

1. **Dates are clean text, so string comparison is correct.** All 5.6M `established_date` and
   `approved_date` values match `^\d{4}-\d{2}-\d{2}$` (no nulls, no other formats).
   `established_date >= '2026-01-01'` and `established_date::date >= '2026-01-01'` returned
   the same count (348,385) in the same time (13.7 s vs 13.9 s). The server's warning about
   casting is stricter than needed. The date-cast lint in `company-db` is therefore a warning
   for non-ISO literals only (e.g. `'2026-8-1'`), not for every uncast comparison.
2. **`date_trunc` returns UTC timestamps, shifted by the server's time zone.**
   `date_trunc('quarter', established_date::date)` gave `2025-12-31T16:00:00+00:00` for Q1
   2026. Group by text instead: `LEFT(established_date, 7)` for months,
   `LEFT(established_date, 4)` for years, `to_char(established_date::date, 'YYYY-"Q"Q')` for
   quarters. The skill says so, and the lint warns on `date_trunc`.
3. **Coverage differs by city, and 深圳 stopped in May.**

   | City | `established_date` | Latest `approved_date` | Latest `updated_at` |
   |---|---|---|---|
   | 杭州市 | 2017-07-19 → 2026-09-30 | 2026-10-19 | 2026-10-21 |
   | 深圳市 | 2020-01 → 2026-05-20 | 2026-06-23 | 2026-06-24 |

   深圳 has zero companies for 2026-06 onward, and status changes there are four months old.
   A comparison of the two cities must cut both to the common window (2020-01 → 2026-05-20),
   and any 深圳 answer about "now" says its data ends in June. Coverage is read at runtime
   (`MAX(established_date)` per city, cached per process), not hard-coded.
4. **Nearly half the rows are 个体工商户.** `enterprise_type = '个体工商户'`: 2,617,244 of
   5,619,655 (47%). "企业" questions are ambiguous: the agent counts both and says how many are
   个体工商户, or excludes them when the user says 公司/企业 in the narrow sense. The skill sets
   the default: report both, lead with the figure excluding 个体工商户.
5. **Registered capital needs parsing and is often empty.** 31% null (1,746,509), 3,221 `-`.
   Of the rest, 99.8% are `万人民币`; 15 other units (`万美元` 2,474, `万港元` 1,670, `万欧元` 123,
   `万港币`, `万日元`, …, and a bare `万`). Working RMB parse:
   `substring(registered_capital from '^[0-9.]+')::numeric` with
   `registered_capital LIKE '%万人民币'`. Capital questions say they count only RMB values and
   how many rows had none. `paid_in_capital` is 93% null: do not analyse it as a measure.
6. **Other columns.**
   - `enterprise_size`: 微型 4.15M, 小型 998k, 中型 217k, 大型 56k, null 197k, `-` 265.
   - `industry_category`: 19 门类, 16% null (881,286). Industry breakdowns show the null row.
   - `insured_person_count`: text integers, 69% null, `0` for 1.16M.
   - `province`: 杭州 rows carry both `浙江省` and `浙江` (3,748). Filter by `city`, not
     `province`.
   - `district_county`: 14 values for 杭州 (one row says `杭州市`), 10 for 深圳.
   - `enterprise_type`: free text with full- and half-width bracket variants of the same type
     (`有限责任公司（自然人投资或控股的法人独资）` and `…(…)`). Group with `LIKE` patterns, not
     equality.
   - Status: 存续 4.14M, 注销 1.40M, 吊销 51k, 正常 23k, 在业 3.9k, 责令关闭 3.2k, 撤销 1.3k,
     others under 200. "Operating" = 存续 + 在业 + 正常; "closed" = 注销 + 吊销 + 撤销 + 责令关闭.
7. **Contact data is common.** Mobile 1.73M (31%), more phones 771k, email 1.64M (29%), legal
   representative 99.9%, website 41k. This confirms the plan's default: stripped from results
   unless `EXPOSE_CONTACTS=true`.
8. **Results the cookbook can start from** (all ~13 s):
   - 杭州 new registrations per month, 2025-10 → 2026-09: 31.6k … 53.4k (2026-02 low at 18.7k).
   - 杭州 2026-08 by district: 萧山 18.9%, 余杭 14.3%, 钱塘 9.8% … (CTE + window).
   - 杭州 2026 RMB capital buckets: <100万 90,762; 100–1000万 39,640; 1000–5000万 5,367;
     ≥5000万 969.
   - 深圳 closed share by cohort: 2020 39.8%, 2022 25.8%, 2024 16.4%, 2026 1.0%.

## Consequences for the plan

- Coverage is computed at startup and stated in answers; the plan's coverage table is
  corrected (深圳 ends 2026-05-20).
- The skill's pitfalls list: 个体工商户 share, RMB-only capital, `date_trunc` time zone,
  `city` not `province`, bracket variants in `enterprise_type`, null rows in breakdowns.
- Golden questions for 0.3 can use the figures in finding 8 as expected answers, re-measured
  when the data moves.
